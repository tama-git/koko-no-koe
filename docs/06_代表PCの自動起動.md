# 代表PCのDjango自動起動

代表PCはDjango・SQLiteを動かし、メンバーは各自のPCでExpoだけを動かします。このスクリプトは代表PC用です。

## 学校・自宅での起動

`koko-no-koe/` で、どちらでも同じコマンドです。

```powershell
.\start-dev.ps1
```

1. 接続中の物理Wi-Fi・有線LANから、IPv4とデフォルトゲートウェイのあるものを探します。仮想アダプター、切断中、ループバック、自動割当のリンクローカルIPを除外します。
2. Windowsの経路とインターフェースの優先度の合計が小さい接続を選びます。表示された接続名・IPが、全員の使うネットワークのものか確認してください。両方が同順位なら停止します。
3. 既存の `admin/backend/.venv/Scripts/python.exe` でDjangoを読み込めるか確認します。
4. 選んだIPを、そのプロセスの `DJANGO_EXTRA_ALLOWED_HOSTS` に設定します。`settings.py` の既存の読み込み処理を使い、IPやワイルドカードをソースに追加しません。
5. 自分の `mobile/frontend/.env.local` の `EXPO_PUBLIC_API_BASE_URL` だけを更新します。ほかの設定やコメントを保持します。
6. 現在のターミナルでDjangoを `0.0.0.0:8000` で起動します。停止はCtrl+Cです。Expoは起動しません。

`0.0.0.0` は接続を受けるための指定です。iPhoneやメンバーがAPI接続先に入力する値は、ターミナルに表示された `API URL` のほうです。

ネットワーク確認だけを行う場合、次のコマンドではファイルの更新や起動をしません。

```powershell
.\start-dev.ps1 -CheckOnly
```

Wi-Fiと有線LANの両方がある場合など、別の接続を使いたいときは次で確認・指定できます。

```powershell
Get-NetAdapter -Physical
.\start-dev.ps1 -InterfaceIndex <使う接続のifIndex>
```

物理接続の優先度と、チーム全員が使う接続が一致するとは限りません。VPN接続をAPI共有に使う構成は対象外です。ネットワークが切り替わったらDjangoを停止し、再実行してください。ポート8000が使用中なら、既存の起動元を確認して停止します。スクリプトは他のプロセスを強制終了しません。

## 自分・メンバーのExpo

代表PCの使用者も、別ターミナルの `mobile/frontend/` でExpoを起動します。

```powershell
npx.cmd expo start --go --lan
```

メンバーは代表PCに表示された `API URL` を自分の `.env.local` の `EXPO_PUBLIC_API_BASE_URL` に設定してから、同じコマンドでExpoを起動します。メンバー側でこのスクリプト、Django、マイグレーションを実行する必要はありません。

既にExpoが起動していたら、接続先変更後に停止・再起動し、Expo Goを再読み込みしてください。代表PCとメンバーPC、iPhoneが互いに通信できるネットワークである必要があります。学校Wi-Fiの端末間通信制限はスクリプトでは解除できません。

## 設定と安全性

- スクリプトはASCIIの英語のみです。Windows PowerShell 5.1でも、BOMなしUTF-8の日本語を誤読して構文エラーになる問題を避けます。
- `.env.local` はUTF-8（BOMの有無）、UTF-16のBOM付きファイルと既存の改行を保持します。読み取れない文字コードなら、上書きせずエラーになります。
- `.env.local` は既存の `.gitignore` で除外されています。IPや秘密情報をコミットしないでください。
- DBの初期化、マイグレーション、セキュリティ設定・実行ポリシー・ファイアウォールの変更、依存のインストールは行いません。
- 学校・自宅でHTTPを使う開発確認用です。Djangoが起動したことと、全員のiPhoneからログインできたことは別に確認します。

## 確認方法

PowerShellの構文、ネットワークの選択・失敗・曖昧さ、環境ファイルの設定保持は、実DBを使わず次で確認できます。

```powershell
powershell.exe -NoProfile -File .\scripts\tests\start-dev.Tests.ps1
```

実機では、表示IPを確認→Expo再起動→架空会員で登録・ログイン→仮トップ→ログアウトを確認します。代表PCのDjangoにリクエストが届くかも見てください。パスワード・トークンを報告や画面共有に載せないでください。

## 今回の確認結果（2026年11月4日）

- 元ファイルはBOMなしUTF-8でした。Windows PowerShell 5.1のファイル解析で7件の構文エラーを再現し、ASCII化後はエラーがなくなりました。
- Windows PowerShell 5.1で自動テスト成功。実際の学校Wi-Fiの選択も確認しました。
- 既存の仮想環境PythonでDjangoが起動し、更新した接続先からログイン画面が200を返しました。会員APIはGETを405、入力不足のPOSTを400で返し、LANのHostを受け入れることを確認しました。
- 会員APIの既存テスト4件がメモリ上のDBで成功しました。実DBにはテスト用アカウントを作っていません。
- 検証用に起動したDjangoは停止しました。アプリ画面や認証コードは今回変更していません。
- 自宅のネットワーク、メンバーPCからの接続、iPhoneでの実ログインは未確認です。
