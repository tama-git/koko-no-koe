# フォルダー構成と開発手順

## 1．最初にモバイル・管理者を分ける

```text
koko-no-koe/
├─ mobile/
│  ├─ frontend/
│  │  ├─ App.tsx                  iPhoneの仮画面
│  │  ├─ app.json                 iPhoneアプリの設定
│  │  ├─ package.json             Node.jsで使う部品の一覧
│  │  ├─ package-lock.json        部品のバージョンの記録
│  │  └─ assets/                  iPhoneアプリの画像
│  └─ backend/                   未実装。今後の処理用の置き場所
├─ admin/
│  ├─ frontend/
│  │  ├─ templates/admin_preview/ 管理者画面のHTML
│  │  └─ static/admin_preview/    管理者画面のCSS
│  └─ backend/
│     ├─ manage.py               Djangoを起動する入口
│     ├─ requirements.txt        Pythonで使う部品の一覧
│     ├─ config/                 Django全体の設定とURL
│     └─ preview/                仮画面の処理・サンプルデータ
├─ docs/                         説明資料
├─ .gitignore                    GitHubに送らないファイルの指定
├─ LICENSE
└─ README.md                     リポジトリの入口の説明
```

フロントエンドは「見た目」、バックエンドは「データやリクエストを扱う処理」です。管理者側はDjangoがHTMLを読み込んで返します。HTMLの編集のために別のWebサーバーを追加する必要はありません。

`admin/backend/preview/views.py` が必要なサンプルを選び、`admin/frontend/templates/admin_preview/` のHTMLへ渡しています。`admin/backend/config/settings.py` に、このHTMLとCSSの置き場所を設定しています。

現在はサンプル専用で、データベースへの保存はありません。iPhoneと管理者画面のデータはまだ連動しません。`mobile/backend/` には、未実装であることを示す説明ファイルだけを置いています。共通のAPI（アプリからデータをやり取りする窓口）・データベース・認証の配置は、実装前に決めます。今回のフォルダー分けは、サーバーやデータベースを必ず2つ作るという意味ではありません。

## 2．編集する場所

| 作業 | ファイル |
| --- | --- |
| iPhoneの仮画面 | `mobile/frontend/App.tsx` |
| 管理者の共通部分・メニュー | `admin/frontend/templates/admin_preview/base.html` |
| 管理者の一覧画面 | `admin/frontend/templates/admin_preview/dashboard.html` |
| 管理者の詳細画面 | `admin/frontend/templates/admin_preview/report_detail.html` |
| 管理者の色・余白・配置 | `admin/frontend/static/admin_preview/styles.css` |
| 一覧の絞り込み・詳細表示の処理 | `admin/backend/preview/views.py` |
| サンプルの投稿・通報 | `admin/backend/preview/sample_data.py` |
| メンバー向けの説明 | `docs/` 内のMarkdownファイル |

## 3．ターミナルを2つ使う

| ターミナル | 作業する場所 | 起動するもの | 確認する場所 |
| --- | --- | --- | --- |
| ① | `mobile/frontend/` | Expo | 各自のiPhone |
| ② | `admin/backend/` | Django | そのPCのブラウザー |

サーバーが動いているターミナルには、別のコマンドを続けて入力しません。止める場合は `Ctrl+C`、別の作業をする場合は新しいターミナルを開きます。

## 4．チームで変更を共有する

初回だけ、Gitの作成者名とメールアドレスを設定します。これはExpoログインとは別です。下の名前・メールは例なので、自分のものに置き換えます。公開リポジトリなので、メールアドレスを公開したくない人はGitHubの「Settings → Emails」で確認できる自分のnoreplyアドレスを使います。

```powershell
git config --global user.name "自分の名前"
git config --global user.email "自分のGitHub用メールアドレス"
```

作業の開始時に、リポジトリの一番上で状態を確認します。変更がある場合は消さず、先に保存方法を担当者と確認してください。

```powershell
Set-Location (git rev-parse --show-toplevel)
git status --short
git switch main
git pull --ff-only
```

担当作業用のブランチ（作業を分ける場所）を作ります。以下の名前は例です。各自で重複しない名前にします。

```powershell
git switch -c feature/admin-layout
```

編集・表示確認後、リポジトリの一番上で変更を確認します。

```powershell
git status --short
git diff
```

自分の変更だけを指定して保存します。以下のファイルは例なので、実際に変更したファイルに置き換えます。

```powershell
git add admin/frontend/static/admin_preview/styles.css
git commit -m "管理者画面の余白を調整"
git push -u origin feature/admin-layout
```

GitHubでPull Requestを作り、別のメンバーが画面と変更を確認してからmainへ取り込みます。他人が作業中のブランチやmainを強制的に上書きしません。役割と担当ファイルが重なる場合は、作業前に相談してください。

## 5．GitHubに送らないもの

- `node_modules/`、`.expo/`、`dist/`
- `.venv/`、`__pycache__/`、`db.sqlite3`
- パスワード、アクセストークン、個人用の設定ファイル

これらは `.gitignore` で除外します。`package-lock.json` と `admin/backend/requirements.txt` は共有し、各自のPCで必要な部品をインストールします。

## 6．今回の動作確認

iPhone側は `mobile/frontend/` で実行します。

```powershell
npx.cmd tsc --noEmit
npx.cmd expo export --platform ios --output-dir dist
```

管理者側は `admin/backend/` で実行します。

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
```

自動確認に加え、iPhoneでの表示とタップ、PCブラウザーでの一覧・絞り込み・詳細への移動を確認します。
