# フォルダー構成と開発手順

画面ごとの分担と実装手順は [画面と機能の分担ガイド](04_画面と機能の分担ガイド.md) を読んでください。

## 1．モバイル・管理者と機能の分け方

```text
koko-no-koe/
├─ mobile/
│  ├─ frontend/
│  │  ├─ App.tsx                  表示する画面を切り替える入口
│  │  ├─ src/
│  │  │  ├─ auth/                 登録・ログイン画面と認証の処理
│  │  │  ├─ home/screens/         トップ画面
│  │  │  ├─ shared/components/    全画面共通の表示領域
│  │  │  ├─ map/                  地図の担当場所（説明のみ）
│  │  │  ├─ posts/                投稿の担当場所（説明のみ）
│  │  │  └─ reports/              通報の担当場所（説明のみ）
│  │  ├─ app.json                 アプリの設定
│  │  ├─ package.json             Node.jsで使う部品の一覧
│  │  ├─ package-lock.json        部品のバージョンの記録
│  │  └─ assets/                  アプリの画像
│  └─ backend/                   説明のみ。独立したサーバーは未実装
├─ admin/
│  ├─ frontend/
│  │  ├─ templates/admin_side/    管理者画面のHTML
│  │  └─ static/admin_side/       管理者画面のCSS
│  └─ backend/
│     ├─ manage.py               Djangoを起動する入口
│     ├─ requirements.txt        Pythonで使う部品の一覧
│     ├─ config/                 Django全体の設定とURL
│     ├─ accounts/               管理者・会員のモデルと認証処理
│     │  ├─ admin_side/          管理者のHTML向け処理
│     │  └─ mobile/              会員のHTML向け処理とJSON API
│     └─ preview/                旧サンプル処理
└─ docs/                         説明資料
```

フロントエンドは画面・操作、バックエンドはデータの保存や権限の確認などを担当します。管理者側はDjangoがHTMLを読み込んで返します。管理者画面はReactの画面ではありません。

モバイル向けの認証APIの試作も、現在は `admin/backend/` のDjangoにあります。`mobile/backend/` に同じ処理を重複作成しません。今後の共通API・データベースの配置はチームで確認します。

## 2．編集する場所

| 作業 | ファイル |
| --- | --- |
| トップ画面 | `mobile/frontend/src/home/screens/HomeScreen.tsx` |
| ログイン画面の入口 | `mobile/frontend/src/auth/screens/LoginScreen.tsx` |
| 登録画面の入口 | `mobile/frontend/src/auth/screens/RegisterScreen.tsx` |
| 両画面共通の入力欄 | `mobile/frontend/src/auth/components/AuthForm.tsx` |
| 認証画面の色・余白・配置 | `mobile/frontend/src/auth/styles.ts` |
| 認証の状態・処理 | `mobile/frontend/src/auth/useAuth.ts` |
| 認証の通信・入力条件 | `mobile/frontend/src/auth/api.ts`、`validation.ts` |
| 表示画面の切り替え | `mobile/frontend/App.tsx`（統合担当と調整） |
| 管理者の共通部分・ログイン・トップ | `admin/frontend/templates/admin_side/` 内のHTML |
| 管理者の色・余白・配置 | `admin/frontend/static/admin_side/styles.css` |
| 管理者の認証処理 | `admin/backend/accounts/admin_side/` |
| 会員のAPI | `admin/backend/accounts/mobile/api_views.py`、`api_urls.py` |
| メンバー向けの説明 | `docs/` 内のMarkdownファイル |

`preview/` は旧サンプルです。ファイルが残っていても現在のURLから表示できるとは限りません。トップや認証の担当者は、上の現行ファイルを確認してください。

## 3．ターミナルを2つ使う

| ターミナル | 作業する場所 | 起動するもの | 確認する場所 |
| --- | --- | --- | --- |
| ① | `mobile/frontend/` | Expo | 各自のiPhone |
| ② | `admin/backend/` | Django | そのPCのブラウザー |

サーバーが動いているターミナルには、別のコマンドを続けて入力しません。止める場合は `Ctrl+C`、別の作業をする場合は新しいターミナルを開きます。

## 4．チームで変更を共有する

初回だけ、Gitの作成者名とメールアドレスを設定します。これはExpoログインとは別です。下の名前・メールは例なので、自分のものに置き換えます。公開リポジトリなので、メールアドレスを公開したくない人はGitHubの「Settings → Emails」で確認できる自分のnoreplyアドレスを使います。

```powershell
git config --global user.name "自分の名前"
git config --global user.email "自分のGitHub用メールアドレス"
```

作業の開始時に、リポジトリの一番上で状態を確認します。変更がある場合は消さず、先に保存方法を担当者と確認してください。

```powershell
Set-Location (git rev-parse --show-toplevel)
git status --short
git switch main
git pull --ff-only
```

担当作業用のブランチ（作業を分ける場所）を作ります。以下の名前は例です。各自で重複しない名前にします。

```powershell
git switch -c feature/admin-layout
```

編集・表示確認後、リポジトリの一番上で変更を確認します。

```powershell
git status --short
git diff
```

自分の変更だけを指定して保存します。以下のファイルは例なので、実際に変更したファイルに置き換えます。

```powershell
git add admin/frontend/static/admin_side/styles.css
git commit -m "管理者画面の余白を調整"
git push -u origin feature/admin-layout
```

GitHubでPull Requestを作り、別のメンバーが画面と変更を確認してからmainへ取り込みます。他人が作業中のブランチやmainを強制的に上書きしません。役割と担当ファイルが重なる場合は、作業前に相談してください。

## 5．GitHubに送らないもの

- `node_modules/`、`.expo/`、`dist/`
- `.venv/`、`__pycache__/`、`db.sqlite3`
- パスワード、アクセストークン、個人用の設定ファイル

これらは `.gitignore` で除外します。`package-lock.json` と `admin/backend/requirements.txt` は共有し、各自のPCで必要な部品をインストールします。

## 6．今回の動作確認

iPhone側は `mobile/frontend/` で実行します。

```powershell
npx.cmd tsc --noEmit
npx.cmd expo export --platform ios --output-dir dist
```

管理者側は `admin/backend/` で実行します。

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
```

自動確認に加え、iPhoneでの表示とタップ、PCブラウザーでの一覧・絞り込み・詳細への移動を確認します。
