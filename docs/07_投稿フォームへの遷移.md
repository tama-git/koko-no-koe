# トップから投稿フォームへの接続

## 今回の範囲

トップ下部の固定バーをタップすると、チーム作成の `PostCreateScreen` を全画面モーダルで表示します。バーは入力欄の見た目ですが、文字入力は開いたフォームで行います。

```text
HomeScreen
├─ HomeMap（モーダル中も保持）
├─ PostBottomSheet（固定バーの高さを除く領域で上下する）
├─ MessageInputBar（画面下部に固定）
└─ PostComposerModal
   ├─ PostCreateScreen（入力内容・写真を保持）
   └─ PostConfirmScreen（確認・最終送信）
```

投稿フォームの `navigation.navigate('PostConfirm', params)` を接続部品が受け取り、確認画面へデータを渡します。`goBack()` は作成画面へ戻り、`popToTop()` はモーダルを閉じて地図へ戻ります。React Navigation等のライブラリを使った汎用ナビゲーションではなく、現在のフォームに必要な呼び出しだけを接続しています。

確認画面へ進んでも作成画面をアンマウントしないため、「入力画面に戻って修正する」で文章・写真を維持します。作成画面の「閉じる」は破棄確認を表示します。確認画面での戻る操作は、既存フォームのボタンを使います。

地図とシートはモーダルを開いても作り直しません。閉じたときに地図の閲覧位置やシートの状態を維持します。アプリ再起動後の位置保存は実装していません。

## 変更箇所

- `mobile/frontend/src/home/components/MessageInputBar.tsx`：固定バー。
- `mobile/frontend/src/home/screens/HomeScreen.tsx`：バーとモーダルを接続。
- `mobile/frontend/src/home/components/PostBottomSheet.tsx`：バーに一覧が隠れないよう、利用する領域の下端を調整。
- `mobile/frontend/src/posts/components/PostComposerModal.tsx`：既存フォームと確認画面への接続。
- `mobile/frontend/src/posts/postService.ts`：接続先未設定のエラーを、モジュール読み込み時から実際の通信時へ変更。送信項目やエンドポイントは維持。
- `mobile/frontend/tests/post-service.test.cjs`：未設定時の読み込み、通信時の拒否、既存送信項目を疑似通信で検証。

## 実機確認

1. Expoを再読み込みし、ログインしてトップを開きます。
2. シートを最小・半分・最大へ動かしても、固定バーが使えることと、投稿一覧がバーに隠れずスクロールできることを確認します。
3. 固定バーから投稿フォームを開き、ダイナミックアイランドやホームバーにボタンが隠れないか確認します。
4. 文章や写真を入力して確認画面へ進み、「修正する」で内容が残るか確認します。既存フォームが位置情報の許可・取得を行います。
5. 作成画面の「閉じる」で「続ける」「投稿をやめる」を確認します。閉じた後、地図の位置とシートが保たれることを確認します。

## サーバー保存は別途確認

今回の画面接続は、投稿APIの保存成功を保証するものではありません。サーバー側の `posts/serializers.py` は `rest_framework` を使用します。画面接続後のユーザー承認によりDRF 3.18.3を既存の仮想環境へ導入し、`requirements.txt` と `INSTALLED_APPS` へ追加しました。Djangoは5.2.18を維持しています。

その後のユーザー承認により、投稿モデルの画像項目に必要なPillow 13.0.0も既存の仮想環境へ導入し、`requirements.txt` に記録しました。投稿テーブルのマイグレーション、認証・権限、フォームとAPIの送信項目の一致などは投稿担当と別途確認が必要です。DB変更・マイグレーションは行っていません。

代表PCで依存をそろえるコマンドは、`admin/backend` で `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` です。Expoだけ動かすメンバーPCにはPython側のライブラリ導入は不要です。

`serializers.py` はDBデータとAPIの送受信項目を変換・検証するPythonソースです。ファイルを個別にダウンロードするものではなく、`from rest_framework import serializers` が使うライブラリはDjango REST Frameworkです。

現在の投稿詳細画面への導線や、投稿後の一覧・ピンの更新は今回の対象外です。フォームの写真・GPS・公開設定・投稿内容の検証処理はチームの実装を維持しています。
