# チームの起動手順：iPhoneと管理者用の仮ページ

対象：すでにGitHubから取得し、各自のiPhoneで表示できたメンバー。

## 1．今回変わったこと

最初に `mobile/`（モバイル）と `admin/`（管理者）を分け、それぞれに `frontend/` と `backend/` を置きました。これまで直下にあった `App.tsx`、`package.json`、`assets` などは `mobile/frontend/` に移動しました。管理者画面のHTML・CSSは `admin/frontend/`、Djangoの処理は `admin/backend/`、資料は共通の `docs/` です。`mobile/backend/` はまだ未実装です。

個人のPCにあるフォルダーの場所は、人によって異なります。`C:\Users\otsuka\koko-no-koe` など、これまで使用したフォルダーをそのまま使ってください。再度cloneする必要はありません。

この資料はPowerShell用です。先頭に `PS` がある画面で、コードを1行ずつ実行します。`PS C:\...>` という表示そのものは入力しません。各コマンドが完了してから次へ進み、エラーが出たらそこで止めます。

## 2．GitHubから新しい構成を取得する

1. Expoなどのサーバーが動いているターミナルでは `Ctrl+C` で停止する。
2. VS Codeで、これまで使っていた `koko-no-koe` フォルダーを開く。
3. 新しいPowerShellターミナルを開く。
4. 次を実行して、リポジトリの一番上に移動する。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

変更したファイルがないか確認します。

```powershell
git status --short
```

何も表示されなければ次へ進みます。変更が表示された場合は、消したり上書きせず、担当者に確認してください。自分で作業中のブランチがある場合も、先に担当者と確認します。

```powershell
git switch main
```

```powershell
git pull --ff-only
```

左側に `mobile`、`admin`、`docs` が表示されれば新しい構成です。

## 3．ターミナル①：iPhone側を起動する

リポジトリの一番上から、iPhoneアプリの場所に移動します。

```powershell
Set-Location .\mobile\frontend
```

```powershell
npm.cmd ci
```

新しい配置で必要な部品を用意するため、構成変更の取得後は一度実行してください。以前の場所に残った `node_modules` を移動・削除する必要はありません。

```powershell
npx.cmd expo whoami
```

自分のユーザー名が表示されれば、ログイン操作は不要です。`Not logged in` の場合だけ、次の2行を順に実行します。

```powershell
$env:BROWSER = "none"
```

```powershell
npx.cmd expo login --browser
```

表示された新しい `https://expo.dev/login?...` のURL全体をコピーし、そのPCのChromeかEdgeのアドレス欄に貼り付けます。ターミナルは `Waiting for browser login...` のまま開いておきます。iPhoneのExpo Goと同じ自分のアカウントでログイン・承認し、ターミナルの完了表示を待ってから `npx.cmd expo whoami` で再確認します。

起動します。

```powershell
npx.cmd expo start --go --lan
```

PCとiPhoneを同じWi-Fiにつなぎ、自分のPCのQRコードをiPhoneの標準カメラで読みます。Expo Goで「旅日記」が表示され、ボタンで数字が増えれば成功です。このターミナルは開いたままにします。

## 4．管理者側に必要なPythonを確認する

VS Codeの「ターミナル」→「新しいターミナル」で2つ目を開きます。次の表示確認は、どのフォルダーからでも実行できます。

```powershell
py -3.13 --version
```

`Python 3.13.x` と表示されれば次へ進みます。認識されない場合は [初めての環境構築](02_初めての環境構築.md) のPython準備を行ってから、VS Codeをすべて閉じて開き直してください。

チームの新規準備はPython 3.13にそろえます。すでに3.12または3.14がある人もDjango 5.2で利用できますが、以下の `py -3.13` を自分の番号に読み替えてください。3.15はこの構成の対応対象外です。

## 5．ターミナル②：管理者側を起動する

2つ目のターミナルで、リポジトリの一番上に戻ります。ターミナル①には入力しません。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

```powershell
Set-Location .\admin\backend
```

`manage.py` と `requirements.txt` がある場所が正解です。

初回だけ、このプロジェクト専用のPython環境（仮想環境）を作ります。

```powershell
py -3.13 -m venv .venv
```

必要な部品を入れます。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

起動します。`Activate.ps1` を実行する必要はありません。

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

`Starting development server at http://127.0.0.1:8000/` と表示されたら、そのPCのChromeかEdgeで以下を開きます。

http://127.0.0.1:8000/

このURLは、その人のPC自身を指します。別の人のサーバーに接続する操作ではありません。管理者側の仮画面に、ExpoへのログインやQRコードは不要です。

## 6．管理者用の仮ページで確認すること

- 「管理者用の仮ページ」と緑色のメッセージが表示される。
- サンプル通報が3件表示される。
- 「未確認」で2件、「確認済み」で1件に絞り込める。
- 「詳細を見る」で対象のサンプル投稿が表示される。
- 「一覧に戻る」で最初の画面に戻る。

「投稿を非表示にする」は未実装のため押せません。ログイン・権限・保存・実際の投稿の変更・iPhoneとのデータ共有も、これからの実装です。Django標準の `/admin/` ではなく、上のトップページを開いてください。

## 7．次回の再開と終了

次回は更新を取得したあと、ターミナル①は `mobile/frontend/` でExpoを、ターミナル②は `admin/backend/` でDjangoを起動します。仮想環境を毎回作り直す必要はありません。`package-lock.json` が変わったときは `npm.cmd ci`、`requirements.txt` が変わったときはpipのインストールをやり直します。

終了するときは、それぞれのターミナルで `Ctrl+C` を押します。

## 8．よくあるエラー

| 表示 | 確認すること |
| --- | --- |
| `npm ci` で `package-lock.json` がない | `mobile/frontend/` に移動したか。リポジトリ直下では実行しない |
| Expoログインで `cmd.exe /c start` エラー | PowerShellで `$env:BROWSER = "none"` を入れてからログインをやり直し、新しいURLを同じPCで開く |
| ブラウザーで `localhost 接続拒否` | ログイン待機中のターミナルが終了していないか。古いURLを再利用していないか |
| `.venv\Scripts\python.exe` が見つからない | `admin/backend/` にいるか。仮想環境の作成が完了しているか |
| `No module named django` | `.venv` のPythonで、`requirements.txt` のインストールが完了しているか |
| `That port is already in use` | 以前のDjangoサーバーを `Ctrl+C` で止める。別ポートを使う場合は `127.0.0.1:8001` で起動し、ブラウザーも同じポートを開く |
| 管理画面に接続できない | ターミナル②のサーバーが動いているか。URLが `http://127.0.0.1:8000/` になっているか |
| iPhoneが接続できない | PCと同じWi-Fiか。PCとExpo Goのアカウントが同じか。Expo Goのローカルネットワーク許可があるか |

エラー時はコマンドとエラー全文を共有してください。パスワードやアクセストークンは共有しません。`npm audit fix --force` やファイルの削除で自己判断の修復はせず、表示内容を確認してから対応します。
