# チームの起動・編集・GitHub共有手順

> モバイル認証の試作を確認するときは、この資料の旧来の仮画面手順に加え、[会員認証の説明](../mobile/frontend/src/auth/README.md) のDjango・接続先設定を使用してください。

対象：すでにGitHubから取得し、各自のiPhoneで表示できたメンバー。

iPhoneと管理者画面の起動は1〜8章、編集した内容のアップロードは [9章](#github-upload)、ほかのメンバーの変更の取得は [10章](#get-team-changes) を使います。コマンドはすべてPowerShellで1行ずつ実行してください。

## 1．今回変わったこと

最初に `mobile/`（モバイル）と `admin/`（管理者）を分け、それぞれに `frontend/` と `backend/` を置きました。これまで直下にあった `App.tsx`、`package.json`、`assets` などは `mobile/frontend/` に移動しました。管理者画面のHTML・CSSは `admin/frontend/`、Djangoの処理は `admin/backend/`、資料は共通の `docs/` です。`mobile/backend/` はまだ未実装です。

個人のPCにあるフォルダーの場所は、人によって異なります。`C:\Users\otsuka\koko-no-koe` など、これまで使用したフォルダーをそのまま使ってください。再度cloneする必要はありません。

この資料はPowerShell用です。先頭に `PS` がある画面で、コードを1行ずつ実行します。`PS C:\...>` という表示そのものは入力しません。各コマンドが完了してから次へ進み、エラーが出たらそこで止めます。

## 2．GitHubから新しい構成を取得する

1. Expoなどのサーバーが動いているターミナルでは `Ctrl+C` で停止する。
2. VS Codeで、これまで使っていた `koko-no-koe` フォルダーを開く。
3. 新しいPowerShellターミナルを開く。
4. 次を実行して、リポジトリの一番上に移動する。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

変更したファイルがないか確認します。

```powershell
git status --short
```

何も表示されなければ次へ進みます。変更が表示された場合は、消したり上書きせず、担当者に確認してください。自分で作業中のブランチがある場合も、先に担当者と確認します。

```powershell
git switch main
```

```powershell
git pull --ff-only
```

左側に `mobile`、`admin`、`docs` が表示されれば新しい構成です。

## 3．ターミナル①：iPhone側を起動する

リポジトリの一番上から、iPhoneアプリの場所に移動します。

```powershell
Set-Location .\mobile\frontend
```

```powershell
npm.cmd ci
```

新しい配置で必要な部品を用意するため、構成変更の取得後は一度実行してください。以前の場所に残った `node_modules` を移動・削除する必要はありません。

```powershell
npx.cmd expo whoami
```

自分のユーザー名が表示されれば、ログイン操作は不要です。`Not logged in` の場合だけ、次の2行を順に実行します。

```powershell
$env:BROWSER = "none"
```

```powershell
npx.cmd expo login --browser
```

表示された新しい `https://expo.dev/login?...` のURL全体をコピーし、そのPCのChromeかEdgeのアドレス欄に貼り付けます。ターミナルは `Waiting for browser login...` のまま開いておきます。iPhoneのExpo Goと同じ自分のアカウントでログイン・承認し、ターミナルの完了表示を待ってから `npx.cmd expo whoami` で再確認します。

起動します。

```powershell
npx.cmd expo start --go --lan
```

PCとiPhoneを同じWi-Fiにつなぎ、自分のPCのQRコードをiPhoneの標準カメラで読みます。Expo Goで「ここの声」のログイン画面が表示されれば接続成功です。このターミナルは開いたままにします。会員登録・ログインのサーバー接続は準備中です。

## 4．管理者側に必要なPythonを確認する

VS Codeの「ターミナル」→「新しいターミナル」で2つ目を開きます。次の表示確認は、どのフォルダーからでも実行できます。

```powershell
py -3.13 --version
```

`Python 3.13.x` と表示されれば次へ進みます。認識されない場合は [初めての環境構築](02_初めての環境構築.md) のPython準備を行ってから、VS Codeをすべて閉じて開き直してください。

チームの新規準備はPython 3.13にそろえます。すでに3.12または3.14がある人もDjango 5.2で利用できますが、以下の `py -3.13` を自分の番号に読み替えてください。3.15はこの構成の対応対象外です。

## 5．ターミナル②：管理者側を起動する

2つ目のターミナルで、リポジトリの一番上に戻ります。ターミナル①には入力しません。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

```powershell
Set-Location .\admin\backend
```

`manage.py` と `requirements.txt` がある場所が正解です。

初回だけ、このプロジェクト専用のPython環境（仮想環境）を作ります。

```powershell
py -3.13 -m venv .venv
```

必要な部品を入れます。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

起動します。`Activate.ps1` を実行する必要はありません。

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

`Starting development server at http://127.0.0.1:8000/` と表示されたら、そのPCのChromeかEdgeで以下を開きます。

http://127.0.0.1:8000/

このURLは、その人のPC自身を指します。別の人のサーバーに接続する操作ではありません。管理者側の仮画面に、ExpoへのログインやQRコードは不要です。

## 6．管理者用の仮ページで確認すること

- 「管理者用の仮ページ」と緑色のメッセージが表示される。
- サンプル通報が3件表示される。
- 「未確認」で2件、「確認済み」で1件に絞り込める。
- 「詳細を見る」で対象のサンプル投稿が表示される。
- 「一覧に戻る」で最初の画面に戻る。

「投稿を非表示にする」は未実装のため押せません。ログイン・権限・保存・実際の投稿の変更・iPhoneとのデータ共有も、これからの実装です。Django標準の `/admin/` ではなく、上のトップページを開いてください。

## 7．次回の再開と終了

次回は更新を取得したあと、ターミナル①は `mobile/frontend/` でExpoを、ターミナル②は `admin/backend/` でDjangoを起動します。仮想環境を毎回作り直す必要はありません。`package-lock.json` が変わったときは `npm.cmd ci`、`requirements.txt` が変わったときはpipのインストールをやり直します。

終了するときは、それぞれのターミナルで `Ctrl+C` を押します。

## 8．よくあるエラー

| 表示 | 確認すること |
| --- | --- |
| `npm ci` で `package-lock.json` がない | `mobile/frontend/` に移動したか。リポジトリ直下では実行しない |
| Expoログインで `cmd.exe /c start` エラー | PowerShellで `$env:BROWSER = "none"` を入れてからログインをやり直し、新しいURLを同じPCで開く |
| ブラウザーで `localhost 接続拒否` | ログイン待機中のターミナルが終了していないか。古いURLを再利用していないか |
| `.venv\Scripts\python.exe` が見つからない | `admin/backend/` にいるか。仮想環境の作成が完了しているか |
| `No module named django` | `.venv` のPythonで、`requirements.txt` のインストールが完了しているか |
| `That port is already in use` | 以前のDjangoサーバーを `Ctrl+C` で止める。別ポートを使う場合は `127.0.0.1:8001` で起動し、ブラウザーも同じポートを開く |
| 管理画面に接続できない | ターミナル②のサーバーが動いているか。URLが `http://127.0.0.1:8000/` になっているか |
| iPhoneが接続できない | PCと同じWi-Fiか。PCとExpo Goのアカウントが同じか。Expo Goのローカルネットワーク許可があるか |

エラー時はコマンドとエラー全文を共有してください。パスワードやアクセストークンは共有しません。`npm audit fix --force` やファイルの削除で自己判断の修復はせず、表示内容を確認してから対応します。

## 9．編集した内容をGitHubへアップロードする

流れは「自分の作業場所を作る → 編集する → 動作確認する → PCに変更を記録する → GitHubに送る → メンバーが確認してmainに取り込む」です。

| 言葉 | 意味 |
| --- | --- |
| main | チームが共有する基本のブランチ |
| ブランチ | 担当者の作業を分ける場所 |
| add | 今回記録するファイルを選ぶ操作 |
| commit | 選んだ変更を自分のPCのGitに記録する操作 |
| push | 記録した変更をGitHubにアップロードする操作 |
| Pull Request（PR） | 変更を確認してmainへ取り込んでもらう依頼 |
| merge | PRの変更をmainへ取り込む操作 |
| pull | GitHubの更新を自分のPCへ取得する操作 |

アップロード先は、チームの [tama-git/koko-no-koe](https://github.com/tama-git/koko-no-koe) です。新しいリポジトリやforkは作らず、各自のブランチを使います。GitHub上の「Upload files」でフォルダーごと送る操作も、この手順では使いません。

**まだ編集していない人**は9-1から順に進めてください。**すでにファイルを編集した人**は9-1のあと9-3へ進みます。9-2のmain切り替え・更新は飛ばし、編集内容を残して作業用ブランチを作ってください。

### 9-1．リポジトリの場所とGitの作成者を確認する

ExpoやDjangoのサーバーが動いているターミナルはそのままにし、VS Codeの「ターミナル」→「新しいターミナル」で、アップロード用のPowerShellを開きます。必ず `koko-no-koe` 内のターミナルを使います。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

これは `mobile/frontend/` や `admin/backend/` にいても、リポジトリの一番上へ戻るコマンドです。`not a git repository` と出たら、VS Codeで `koko-no-koe` フォルダーを開き直してから実行してください。

```powershell
git config --get user.name
```

```powershell
git config --get user.email
```

両方とも自分の情報が表示されれば設定済みです。空欄または別の人の情報の場合は、次の例を自分のものに置き換えて設定します。この設定はこのリポジトリだけに適用され、GitHubへのログインとは別です。

```powershell
git config user.name "自分の名前"
```

```powershell
git config user.email "自分のGitHub用メールアドレス"
```

このリポジトリは公開なので、作成者のメールアドレスも公開されます。個人のメールアドレスを出したくない場合は、GitHubの「Settings → Emails」で確認できる自分のnoreplyアドレスを使ってください。「自分の名前」「自分のGitHub用メールアドレス」という文字を、そのまま登録する操作ではありません。

### 9-2．編集前に、チームの最新版を取得する

この手順は、これから新しい作業を始める人向けです。すでに編集した人は9-3へ進みます。

```powershell
git status --short
```

何も表示されないことを確認します。変更が表示されたら、削除や上書きはせず、9-3の「すでに編集している場合」に進んでください。

```powershell
git switch main
```

```powershell
git pull --ff-only
```

`Already up to date.` と表示された場合も正常です。最新版が取得済みという意味です。

### 9-3．自分の作業用ブランチを作る

次は例です。`yourname` を自分の名前の半角英字、`admin-layout` を作業内容の半角英字に置き換えます。例えば `feature/otsuka-admin-layout` や `feature/fujita-mobile-home` のように、担当者と作業内容が分かり、チーム内で重複しない名前にします。

```powershell
git switch -c feature/yourname-admin-layout
```

確認します。

```powershell
git branch --show-current
```

自分が付けた `feature/...` が表示されれば成功です。

すでに編集している場合も、まずこの操作で現在の編集内容を作業用ブランチに残せます。すでに自分の担当ブランチで作業している場合は、作り直さず、そのブランチ名を確認して9-4へ進みます。他人のブランチや用途の分からないブランチの場合は、変更せず担当者に確認してください。

### 9-4．編集して保存し、動作を確認する

| 編集したいもの | 主なファイル |
| --- | --- |
| iPhoneの画面 | `mobile/frontend/App.tsx` |
| 管理者の一覧画面 | `admin/frontend/templates/admin_preview/dashboard.html` |
| 管理者の詳細画面 | `admin/frontend/templates/admin_preview/report_detail.html` |
| 管理者の見た目 | `admin/frontend/static/admin_preview/styles.css` |
| 管理者の表示処理 | `admin/backend/preview/views.py` |
| 説明資料 | `docs/` 内のMarkdownファイル |

VS Codeで編集したら `Ctrl+S` で保存します。iPhone側はExpo Go、管理者側はDjangoを起動したPCのブラウザーで、変更した箇所を確認します。HTMLやCSSを編集した場合はブラウザーを再読み込みしてください。説明資料だけの変更は、文章とコマンドの内容を確認します。

ブランチを切り替えた際に依存関係のファイルが変わった場合は、7章の手順で部品を更新し、開発サーバーを再起動します。

### 9-5．変更したファイルを確認する

アップロード用のターミナルに戻ります。以下の操作はリポジトリの一番上で実行します。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

```powershell
git status --short
```

`M` は変更、`??` は新しいファイル、`D` は削除を表します。予定していないファイルや削除が含まれていたら、先に確認してください。

```powershell
git diff
```

赤が削除、緑が追加です。表示が長くなり `(END)` などが出た場合は、`q` を押すとコマンド入力へ戻れます。新しい未登録ファイルは通常の `git diff` に表示されないため、VS Codeで中身も確認します。

### 9-6．今回アップロードするファイルを選ぶ

変更したファイルに合わせて、必要な行だけを実行します。全部を実行する必要はありません。

iPhoneの画面を変更した場合：

```powershell
git add mobile/frontend/App.tsx
```

管理者のCSSを変更した場合：

```powershell
git add admin/frontend/static/admin_preview/styles.css
```

管理者の一覧画面を変更した場合：

```powershell
git add admin/frontend/templates/admin_preview/dashboard.html
```

別のファイルを変更した場合は、`git add` の後ろを、リポジトリの一番上から見たファイルの場所に置き換えます。複数ファイルを変更した場合は、それぞれに対して実行します。ファイルの削除も共有したい場合は、削除したファイルの場所を `git add` に指定します。

記録対象を確認します。

```powershell
git diff --cached --stat
```

```powershell
git diff --cached
```

自分が共有したい変更だけが入っていれば次へ進みます。パスワードやアクセストークン、個人用の設定を含めないでください。`node_modules` や `.venv` などの部品そのものは送らず、`.gitignore` の除外を維持します。

### 9-7．自分のPCに変更を記録する（commit）

メッセージは、実際の変更内容に置き換えます。

```powershell
git commit -m "管理者画面の余白を調整"
```

ここまででは、自分のPCに記録しただけです。GitHubへは、次のpushで送ります。

### 9-8．GitHubにアップロードする（push）

まず、自分の作業ブランチであることを確認します。

```powershell
git branch --show-current
```

`main` ではなく、9-3で作成した自分の `feature/...` が表示されることを確認してください。

```powershell
git push -u origin HEAD
```

`HEAD` はそのまま入力します。現在のブランチを、同じ名前でGitHubへ送る指定です。

GitHubの認証画面が開いたら、招待を承認した自分のGitHubアカウントでログインします。ここで使うのはExpoのアカウントではありません。認証エラーの場合は、リポジトリへの参加とログイン先のアカウントを確認してください。トークンをチャットに貼り付ける必要はありません。

成功すると、送信先やブランチ名が表示されます。[リポジトリ](https://github.com/tama-git/koko-no-koe) のブランチ選択を自分のブランチへ切り替え、変更したファイルが反映されているか確認します。pushだけでは、mainやほかの人のPCには反映されません。

### 9-9．メンバーに確認してもらう（Pull Request）

1. GitHubで [koko-no-koe](https://github.com/tama-git/koko-no-koe) を開く。
2. 「Compare & pull request」が表示されていれば押す。なければ「Pull requests」→「New pull request」を開く。
3. **baseは `main`、compareは自分の作業ブランチ**にする。
4. 比較画面の場合は「Create pull request」で入力画面へ進む。すでにタイトル・説明の入力欄が表示されている場合は、そのまま入力する。
5. タイトルと、説明に「変更したこと」「動作確認したこと」「未対応の点があればその内容」を書き、「Create pull request」で作成する。
6. ほかのメンバーにPRのURLを共有し、変更内容と動作を確認してもらう。

追加修正を頼まれたら、同じブランチで編集・確認・add・commit・pushを繰り返します。同じブランチのpushは、作成済みのPRにも反映されます。

### 9-10．確認した変更をmainへ取り込む

チームで決めた確認担当者が、内容を確認してからGitHubのPR画面で「Merge pull request」→「Confirm merge」を行います。取り込み完了まで、mainには変更が入りません。

競合（conflict）が表示される場合は、自分とほかの人の編集が重なっている可能性があります。その場で片方の変更を消したり、強制pushしたりせず、対象ファイルと表示を担当者に共有してから解決します。

## 10．ほかのメンバーがアップロードした変更を取得する

PRがmainに取り込まれたあと、各自のPCで更新します。自分がアップロードした本人も同じです。

1. 作業中の変更を自分のブランチにcommitして、状態を確認する。
2. 動かしているExpo・Djangoは `Ctrl+C` で停止する。
3. アップロード用ターミナルで、リポジトリの一番上へ移動する。

```powershell
Set-Location (git rev-parse --show-toplevel)
```

```powershell
git status --short
```

何も表示されないことを確認してから、次へ進みます。変更が残っている場合は、消したり上書きせず担当者に確認してください。

```powershell
git switch main
```

```powershell
git pull --ff-only
```

更新後は3章・5章の場所でサーバーを起動します。`package-lock.json` が変わった場合は `mobile/frontend/` で `npm.cmd ci`、`requirements.txt` が変わった場合は `admin/backend/` でpipのインストールをやり直します。次の新しい作業を始める際は、更新したmainから、別の名前の作業用ブランチを作ってください。

## 11．アップロードで困ったとき

| 表示・状態 | 対応 |
| --- | --- |
| `Author identity unknown` | 9-1の名前・メールを設定してcommitをやり直す |
| `nothing to commit` | `Ctrl+S` で保存済みか、対象ファイルをaddしたか、作業するリポジトリ・ブランチが合っているか確認する。すでにcommit済みならpushへ進む |
| `Everything up-to-date` | 送信する新しいcommitがない。編集を保存・add・commitしたか、現在のブランチが合っているか確認する |
| `Permission denied`、`403`、認証エラー | GitHubの招待を承認したアカウントで認証しているか、書き込み権限があるか確認する |
| `a branch named ... already exists` | 同じ名前のブランチがある。自分の継続作業ならそのブランチを確認し、新しい作業なら重複しない別名を使う |
| `Updates were rejected`、`non-fast-forward` | GitHub側のブランチに別の変更がある。`--force` は使わず、表示全文を担当者に共有する |
| pushしたのにmainが変わらない | PRを作成し、mainへ取り込まれたか確認する |
| mainが変わったのに自分の画面が変わらない | 10章のpullを行い、必要な部品を更新してサーバーを再起動したか確認する |
