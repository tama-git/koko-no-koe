# 投稿の保存と確認

2026年11月5日。既存の投稿作成・確認・詳細画面を活かし、ログイン中の本人による保存と確認を接続しました。

## 使い方

1. 代表PCのDjangoを停止・再起動します。いつもどおりリポジトリ直下で `.\start-dev.ps1` を実行できます。
2. 各自のPCでAPI接続先を確認し、Expoを起動・再読み込みします。ライブラリの追加はありません。
3. ログイン後、トップ下部の固定バーから投稿フォームを開きます。
4. 文章またはその場で撮影した写真を入力し、位置情報を許可して確認画面へ進みます。
5. 「この内容で投稿する」を押し、成功案内のOKを押すと、既存の詳細画面で保存済みデータをサーバーから読み直します。
6. トップ上部の「自分の投稿」を押すと、公開・非公開を含む自分の投稿が表示されます。タップすると詳細を開けます。
7. ボトムシートの「公開投稿」には他の会員の公開投稿も表示されます。別アカウントで確認するときは、シート内の一覧を下に引くと再取得できます。

距離判定を追加するまでは、ログインした会員が場所に関係なく公開投稿を閲覧できます。一覧や詳細の取得に閲覧者の現在地は送りません。非公開投稿は、投稿者本人だけが一覧・詳細・写真を確認できます。

## APIの接続

| 操作 | API | 認証と扱い |
| --- | --- | --- |
| 自分の一覧 | `GET /api/posts/` | モバイルログインのBearerトークンが必要。本人の投稿だけ |
| 公開一覧 | `GET /api/posts/public/` | ログインが必要。公開設定の投稿だけを新しい順に返す |
| 保存 | `POST /api/posts/` | multipart。投稿者はサーバーがトークンから決める |
| 詳細 | `GET /api/posts/<id>/` | 本人の投稿、または公開投稿。閲覧できないIDは404 |
| 写真 | `GET /api/posts/<id>/image/` | 詳細と同じ閲覧条件。保存フォルダーを直接公開しない |

会員登録・ログインAPIは従来のままです。管理者のCookieや `auth.User` では投稿APIを認証しません。無効・期限切れ・ログアウト済みのトークンは401、無効な会員も拒否します。

送信項目は `message`、`image`（任意）、`latitude`、`longitude`、`is_published` です。本文・写真の少なくとも一方、範囲内の緯度・経度、公開指定が必要です。写真は1枚で、画像として検証します。文字数・容量・精度等の正式な上限値は今回決めていません。

DBの既存モデル名 `user_id`・`is_public` は維持し、Serializerで `is_published` を `is_public` に対応させています。会員IDは端末から指定させません。緯度経度はDBの小数点以下7桁に合わせ、詳細画面で数値として扱えるよう応答も整えています。

写真はReact Nativeの `{ uri, name, type }` というファイル情報で送ります。保存先は `admin/backend/media/` で、Gitの除外対象です。画像の保存名はサーバー側のランダム名にし、写真表示時もBearer認証を行います。端末の認証情報を外部の画像URLへ送らないよう、クライアントの取得先も自分の投稿APIに限定しています。

他の会員に写真を返す際は、元画像の向きを補正して、撮影機種やGPSなどの付加情報を含まないJPEGに変換します。保存済みの元画像とDBは変更しません。公開一覧の追加にマイグレーションは不要です。

この代表PCでは適用済みです。メンバーがExpoだけを動かす場合はマイグレーション不要です。別の代表サーバーへ移す場合は、DBと写真を保護して対象を確認してから適用します。バックアップにはアカウント情報を含むため、共有やGitHubへの登録はしないでください。
