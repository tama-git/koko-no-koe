# 地図機能の担当場所

トップ画面では `components/HomeMap.tsx` が WebView を開き、`openFreeMapDocument.ts` の MapLibre GL JS で OpenFreeMap の背景地図を表示します。投稿詳細の小さな地図は `components/PostLocationMap.tsx` が担当します。

- OpenFreeMapのLibertyをもとに、店舗アイコンと店舗名を省きます。駅と主要施設は広い縮尺から、道や歩道とデータにある駅入口は拡大時に表示します。
- 現在地、ピン、一覧は同じ位置情報から更新されます。赤いピンは250m以内で投稿詳細、青いピンは範囲外で直線距離を開きます。
- 地図の表示範囲は最初の位置取得時と「現在地」ボタンで移動します。歩行中は現在地の点と円が動き、表示範囲は手で操作できます。
- WebViewには描画に必要な座標・ピンID・圏内判定だけを渡します。背景地図の読み込みにはインターネット接続が必要です。

試すには `mobile/frontend` で `npm.cmd install` を実行し、`npx.cmd expo start --go --lan --clear` で起動してください。Djangoも通常どおり起動します。Expo Goの位置情報を「アプリの使用中」に許可し、屋外で同じ投稿に近づくと、青いピンが赤に変わり、シートの「近くで読める声」の件数が増えることを確認できます。

## Apple Maps使用時の記録

実際の地図は `components/HomeMap.tsx` です。トップ画面の `../home/screens/HomeScreen.tsx` が地図と既存の `PostBottomSheet` を同じ領域に重ねます。地図のために別画面へ移動しません。

`screens/MapScreen.tsx` は以前作った未接続の画面雛形で、今回の表示には使用しません。`mapService.ts` も未実装の雛形です。今後の地図の修正はまず `components/HomeMap.tsx` を確認してください。

`react-native-maps` をExpo SDKに対応する版で使用し、iPhoneでは既定プロバイダーのApple Mapsを表示します。`initialRegion` は日本全体を見渡すための暫定値で、ユーザーの現在地ではありません。移動・拡大縮小後の領域を固定する `region` は渡していないため、操作後に初期位置へ戻す処理はありません。

Phase 2では、トップ表示時に利用中の位置情報許可を要求し、取得できたら地図の中心を一度だけ現在地へ移動します。以後は地図を自由に移動できます。許可拒否・端末の位置情報オフ・取得失敗・タイムアウトでも地図を操作できます。案内はダイナミックアイランドを避けた上部に表示し、ボトムシートが最大の場合はシートが案内も覆います。

取得成功後はApple Maps標準の現在地表示も有効にします。標準の現在地表示は移動で更新される場合がありますが、地図を中心へ動かす処理は一度だけです。位置情報を保存したりDjangoへ送信したりしません。

トップ地図の赤いピンとボトムシートの公開一覧は、Djangoから取得した同じ投稿データを使います。座標がある公開投稿のピンを押すと、既存の投稿詳細が開きます。詳細下部の `components/PostLocationMap.tsx` は、その投稿の保存済み座標を中心に表示します。閲覧距離の判定は未実装です。

ボトムシート外側の `pointerEvents="box-none"` により、シートが覆っていない部分の地図を操作できます。最大高さでは同じ親領域全体をシートが覆います。

## iPhoneでの確認

1. `mobile/frontend` で `npm.cmd install` を行い、共有された依存をそろえます。地図は `react-native-maps`、位置情報は `expo-location` をExpo互換版で使用します。
2. Djangoをいつもの方法で起動し、API接続先を確認します。
3. Expoを停止・再起動し、`npx.cmd expo start --go --lan` でExpo Goを開きます。古い表示が残る場合は停止して `npx.cmd expo start --go --lan --clear` で起動します。
4. ログイン後、地図が表示されることを確認します。シートを最小にすると初期の地図範囲を広く確認できます。
5. 地図が見えている部分で移動・ピンチ操作を行います。シートのハンドルを動かし、最小・半分・最大への吸着と一覧スクロールが維持されるか確認します。
6. 最大では地図が隠れ、ハンドルを下げると再び見えることを確認します。指を離したときに背後の地図が意図せず移動しないかも確認します。
7. 座標のある公開投稿のピンを押し、一覧と同じ投稿の詳細が開くか確認します。詳細の下部にある地図で、投稿地点を示すピンも確認します。

### Phase 2の追加確認

1. Expoを再起動・再読み込みし、トップを開いて位置情報を許可します。現在地へ中心が移動し、標準の現在地表示が出るか確認します。
2. 地図を手で移動したあと、勝手に現在地へ繰り返し戻されないか確認します。
3. iPhoneの設定でExpo Goの位置情報を許可しない状態にし、アプリを再読み込みします。案内が出て、地図の移動・拡大縮小・シート操作を続けられるか確認します。
4. 端末全体の位置情報オフや、屋内など取得が難しい状況でも、取得待ちが終わり地図を操作できるか確認します。確認後は端末設定を元へ戻してください。
5. 許可を変更した後はアプリを再読み込みしてください。現在地へ戻るボタンはPhase 3で追加予定です。

Expo GoではOSの許可先名がExpo Goになる場合があります。アプリ独自ビルドでの許可文言の設定・検証は別途必要です。位置取得には前景権限のみを使用します。[Expo公式資料](https://docs.expo.dev/versions/v58.0.0/sdk/location/)

Expo SDKとiPhoneに入っているExpo Goの対応バージョンが一致している必要があります。地図表示には通信が必要です。PCでの型検査・iOS向けバンドル確認と、iPhone実機の地図・タッチ操作の確認は別です。

作業前のトップ画面では `onLogout` を受け取るもののログアウトボタンが表示されていません。Phase 1では既存の画面構成を維持しており、この導線は追加していません。認証機能のテストと、実機でログアウトできる導線の確認は区別してください。

位置情報を拒否した場合に許可しているのは地図の操作です。投稿の閲覧・登録や距離による制限は別の規則であり、今後サーバー側の実装と合わせて確認します。

- Expo SDK 58.0.19のローカル互換表と公式資料を確認し、`npx.cmd expo install react-native-maps` で1.29.11を導入しました。追加された間接依存は `@types/geojson` です。

- iOS向けのバンドル生成が成功しました。Apple Mapsの描画と実機のタッチ操作は未確認です。
- `expo install --check` は既存の `react-native@0.88.0` に対して0.88.1を推奨するため警告終了しました。地図以外の依存更新は行っていません。
- npmは依存関係全体について脆弱性11件を報告しました。今回の追加に起因するかは未確認です。範囲外の自動更新・`npm audit fix` は実行していません。
- Phase 1完了時点では位置情報・投稿ピン・API連携は未実装でした。Phase 2の位置情報は今回追加しています。
